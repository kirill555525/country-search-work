## 1. Отмена устаревших запросов

В `src/search-controller.ts` функция `setQuery` при каждом изменении ввода сразу сбрасывает таймер debounce и вызывает `active.abort()`. Отмена происходит до ожидания следующего запроса, поэтому старый ответ не может обновить результаты во время новой задержки.

В `src/cached-search.ts` отменяется подписка текущего потребителя. Если подписчиков больше нет, отменяется общий запрос. В обычном интерфейсе подписчик один, поэтому отмена сразу доходит до `fetch` через связанный контроллер в `src/search-countries.ts`. Другие потребители общего запроса, если они есть, продолжают ждать свой результат.

Один флаг актуальности только запретил бы отображать ответ, но оставил бы сетевой запрос работающим. Здесь используется настоящая отмена через `AbortController`. Проверка `signal.aborted` после `await` дополнительно защищает от уже завершившихся промисов. `AbortError` не показывается пользователю как ошибка.

## 2. Выбор задержки debounce

В `createSearchController` выбрана задержка **300 мс**. Она объединяет быстрые нажатия в один запрос после паузы и сохраняет отзывчивость поиска.

Без debounce запрос отправлялся бы почти на каждый символ: увеличились бы количество запросов и число отмен. При задержке в 1–2 секунды пользователь заметно дольше ждал бы начала поиска. Клик по истории и нажатие Enter запускают поиск сразу.

## 3. Сложность алгоритмов

Для `mapCountryResponse` обозначим количество языков как `L`, валют — `C`, границ — `B`, суммарную длину обрабатываемых строк — `T`. Функция проходит по этим массивам и создаёт новую модель, поэтому время и дополнительная память — **O(L + C + B + T)**.

Для кэша и дедупликации в `src/cached-search.ts`: `Q` — длина запроса, `S` — размер ответа, `U` — количество подписчиков одного запроса.

| Операция                                                                 | Время                               | Дополнительная память |
| ------------------------------------------------------------------------ | ----------------------------------- | --------------------- |
| Нормализация ключа                                                       | O(Q)                                | O(Q)                  |
| Поиск записи, обновление LRU и работа с подпиской после подготовки ключа | В среднем O(1) для операций Map/Set | O(1) на подписку      |
| Получение готового ответа из кэша                                        | O(Q + S)                            | O(Q + S)              |
| Выдача ответа U подписчикам                                              | O(U × S)                            | O(U × S) для копий    |

Получение из кэша не является целиком O(1): `structuredClone` копирует данные за O(S). Память кэша пропорциональна суммарному размеру сохранённых ключей и ответов; число записей ограничено 50. Дедупликация дополнительно хранит ключи активных запросов и подписки; при получении результата каждый подписчик получает свою копию.

## 4. Принципы чистого кода

- **Одна ответственность:** `debounce` в `src/debounce.ts` управляет задержкой; `searchCountries` в `src/search-countries.ts` выполняет запрос; `mapCountryResponse` в `src/map-country.ts` преобразует данные; `createSearchView` в `src/view.ts` создаёт интерфейс.
- **Чистые функции:** `mapCountryResponse` не изменяет исходный объект, а `classifySearchError` в `src/search-error.ts` определяет тип ошибки без побочных эффектов.
- **Передача зависимостей:** `createSearchController` принимает `search` и `onState`, а `createSearchHistory` в `src/search-history.ts` — хранилище. Это позволяет тестировать логику без браузера и реальной сети.
- **Явные контракты:** типы `Country`, `SearchState` и `StoragePort` описывают данные между модулями. Ответ API принимается как `unknown` и проверяется перед использованием.
- **Ранние выходы и освобождение ресурсов:** `searchCountries` отдельно обрабатывает пустой запрос и 404, а в `finally` очищает таймер и обработчик отмены; `dispose` в контроллере прекращает ожидающую и активную работу.
